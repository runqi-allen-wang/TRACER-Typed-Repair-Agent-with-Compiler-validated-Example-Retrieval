WHERE TRACER INTERVENES

The improvement is the repair loop—not a new Lean kernel

TRACER keeps the model replaceable and improves the engineering between generation and acceptance: diagnostics remain traceable, retrieval can react to the current error, and no proof is accepted without compilation.

01Patch safely

Replace only the target proof region in an isolated temporary project; preserve imports and theorem headers.

Effect: source files stay untouched.
02Keep the compiler signal

Store raw diagnostics, normalized categories, structured goals, warnings, and timeouts together.

Effect: compact feedback remains auditable.
03React to the error

Feedback arms expose the latest diagnostic; adaptive retrieval arms rebuild the query from the current error state.

Effect: R-E changed 90% of eligible Flash queries.
04Bound the repair loop

Retry only within a declared round budget, recording every candidate, diagnostic, retrieved example, latency, and usage.

Effect: 76/864 instances recovered after round one.
05Verify, then publish

Reject incomplete proofs and unsafe constructs; save successful files and independently recompile public solutions.

Effect: 811 released proofs recompiled independently.

Boundary: TRACER does not replace Lean, train a new model, or make every feedback arm better. It turns model output into a bounded, compiler-validated, inspectable repair process.
